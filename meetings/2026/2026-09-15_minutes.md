### WebMCP Research Presentation

* Tommaso Innocenti: We will start with Lin-Fa Lee's presentation, “Security Risks and Defenses for WebMCP: From Mid-Session Tool Injection to WebMCP-Phalanx.”

* Lin-Fa Lee: Our research examines whether an agent can still trust tools as a page and its available tools change. We studied tool hijacking, where the implementation behind a familiar tool name changes, and tool framing, where a tool description presents an unauthorized action as part of the expected workflow.

* Lin-Fa Lee: We demonstrated two hijacking paths. An attacker can register a tool name before the site's normal code, or remove an existing registration through an exposed cancellation control and register malicious code under the same name. Checking only for duplicate names does not establish who is authorized to control a registration.

* Lin-Fa Lee: We tested several multi-step tasks across three models. We checked both whether an attacker-controlled tool was called and whether the expected task sequence completed. All three tested models called a replaced tool in the hijacking condition. Completing the expected sequence did not show that a run was safe: an agent could also perform an extra action the user had not requested. Results for description-based framing differed across models.

* Lin-Fa Lee: WebMCP-Phalanx combines control over tool management with a separate agent that checks tool descriptions and returned content. The checking agent cannot call tools; the runtime applies its judgments before passing information to the task agent. A valid management handle does not establish that a tool's content is safe.

* Lin-Fa Lee: Checking a result after execution cannot undo an action or recover data already sent. Sensitive actions need permission checks before execution. We also need to distinguish removing a tool registration, stopping a running tool, and ending an earlier approval.

* Lin-Fa Lee: Our specification suggestions cover stable registration identities, authority to register or change tools, permission checks, data use, and records of what the user approved and what actually happened. We have not yet submitted these proposals to the WebMCP team.

* Lin-Fa Lee: For future research, we would like repeatable attack-and-defense testing with independent evaluation. We need to assess whether defenses preserve useful task completion as well as their time and cost.

* Tommaso Innocenti: Please send the proposed changes to the WebMCP team so they can be discussed as contributions to the specification.

* Action: Lin-Fa Lee: Share the proposed specification changes with the WebMCP team.
